# Contribuer à PlanTrip

> *Un projet Open Source n'est jamais l'œuvre d'une seule personne.*
>
> *Il grandit grâce aux personnes qui choisissent d'y consacrer un peu de leur temps.*

---

# Avant toute chose

Je vous souhaite la bienvenue.

Si vous êtes arrivé jusqu'ici, il y a de fortes chances que PlanTrip ait retenu votre attention.

Alors, avant de parler de code, de Pull Requests ou de conventions de développement, j'aimerais simplement vous dire une chose.

Merci.

Merci de prendre le temps de vous intéresser à ce projet.

Merci d'envisager d'y contribuer.

Dans un monde où tout va toujours plus vite, consacrer quelques minutes à améliorer le travail de quelqu'un d'autre est déjà une forme de générosité.

Je ne l'oublierai jamais.

---

# Pourquoi j'ai choisi l'Open Source

J'aurais pu développer PlanTrip seul.

J'aurais pu garder son code pour moi.

J'ai pourtant choisi une autre voie.

Parce que je suis convaincu qu'un projet devient meilleur lorsqu'il est regardé par plusieurs personnes.

Chacun possède une expérience différente.

Une sensibilité différente.

Une manière différente de résoudre les problèmes.

Aucune personne ne détient toutes les bonnes idées.

Et certainement pas moi.

---

# Je ne suis pas parfait

J'aimerais vous dire quelque chose qui me paraît important.

Je ne suis pas un développeur parfait.

Je ne suis pas un designer parfait.

Je ne suis pas un architecte parfait.

Je suis simplement quelqu'un qui essaie de construire le meilleur projet dont il est capable.

Comme tout le monde, il m'arrive de me tromper.

Il m'arrive de prendre de mauvaises décisions.

Il m'arrive de changer d'avis.

Et j'espère sincèrement que cela continuera.

Parce qu'un projet cesse de progresser le jour où son mainteneur pense avoir toujours raison.

Si un jour vous trouvez une meilleure idée, une architecture plus simple ou une solution plus élégante, j'espère que vous prendrez le temps de me l'expliquer.

Peut-être que je vous convaincrai.

Peut-être que vous me convaincrez.

Dans les deux cas, PlanTrip aura gagné quelque chose.

---

# Ce que j'attends des contributeurs

Je ne cherche pas uniquement des développeurs.

Je cherche des personnes qui auront envie de faire grandir ce projet.

Vous pouvez écrire du code.

Corriger une faute dans la documentation.

Créer une illustration.

Améliorer une interface.

Tester une fonctionnalité.

Signaler un bug.

Poser une question.

Partager une idée.

Toutes ces contributions comptent.

Parce qu'elles participent toutes à construire PlanTrip.

---

# Une seule demande

Je ne vous demanderai jamais de penser comme moi.

Je ne vous demanderai jamais d'être d'accord avec chacune de mes décisions.

Je vous demanderai seulement une chose.

Avant de modifier quelque chose, prenez quelques minutes pour comprendre pourquoi cette décision avait été prise.

Peut-être découvrirez-vous qu'elle était mauvaise.

Peut-être découvrirez-vous qu'elle répondait à une contrainte que vous ignoriez.

Dans les deux cas, vous prendrez une décision plus réfléchie.

C'est tout ce que je souhaite.

---

# Le respect avant tout

Le code peut être critiqué.

Les idées peuvent être discutées.

Les décisions peuvent évoluer.

Les personnes, elles, méritent toujours le respect.

J'aimerais que chacun puisse participer à ce projet sans craindre le jugement ou l'agressivité.

Nous ne sommes pas ici pour avoir raison.

Nous sommes ici pour construire quelque chose de mieux.

Ensemble.

---

# Laisser le projet dans un meilleur état

Je n'attends pas que chaque contribution change PlanTrip. J'espère simplement qu'elle lui apportera quelque chose d'utile. 

Une idée plus claire. 

Un code plus simple. 

Une documentation plus précise. 

Un détail qui rendra le projet un peu meilleur qu'hier.

Une correction.

Une meilleure explication.

Une documentation plus claire.

Un commentaire plus utile.

Une fonction simplifiée.

Aucune amélioration n'est trop petite et chaque contribution compte.

---

# Si un jour...

Aujourd'hui, je suis le mainteneur de PlanTrip.

Peut-être que ce sera encore le cas dans dix ans.

Peut-être pas.

Si un jour d'autres personnes reprennent ce projet, je n'espère pas qu'elles continueront à faire les mêmes choix que moi.

J'espère simplement qu'elles prendront le temps de comprendre les raisons qui les ont motivés.

Un projet évolue.

C'est normal.

Mais il évolue beaucoup mieux lorsque l'on comprend son histoire, son origine.

---

# Les aspects techniques

Pour faciliter la maintenance du projet, quelques règles simples seront progressivement mises en place.

- Des conventions de nommage.
- Une organisation cohérente des fichiers.
- Une documentation systématique.
- Des Pull Requests claires et argumentées.
- Des échanges respectueux.

Ces règles évolueront avec le projet.

Elles ne sont pas là pour compliquer les contributions.

Elles sont là pour les rendre plus simples.

---

# Merci

Si vous avez pris le temps de lire ce document jusqu'au bout, alors vous avez déjà consacré à PlanTrip quelque chose de précieux.

Votre temps.

J'espère sincèrement que cette aventure vous donnera envie de revenir.

Les meilleurs projets ne sont pas ceux qui réunissent les meilleurs développeurs.

Ce sont ceux qui donnent envie aux bonnes personnes de construire quelque chose ensemble.

Bienvenue dans PlanTrip.

Bienvenue dans Projet Atlas.
